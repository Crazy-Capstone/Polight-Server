# 회원 탈퇴

## API

```http
DELETE /api/users/withdraw
Authorization: Bearer <accessToken>
```

- 요청 본문은 없다. 삭제 대상은 인증된 본인이며, 회원 ID를 외부에서 받지 않는다.
- 성공 응답: `204 No Content`.
- 미인증 또는 이미 삭제된 회원의 토큰: `401 Unauthorized`.

## 삭제 범위

- 회원, 여행, 업로드 문서, 분석 결과, 가입 담보, 개인 문서 청크.
- 채팅 세션과 메시지, 알림과 알림 설정.
- 본인 소유 또는 본인 문서를 원본으로 삼는 약관과 그 청크, 보장 규칙, 세부 항목, 한도, 청구 서류, 면책 조건, 근거 인용.
- Redis에 남아 있는 본인의 리프레시 토큰.
- 현재 설정된 로컬 또는 S3 저장소의 원본 업로드 파일.

운영자가 등록한 공용 약관과 공용 긴급 연락처는 회원 데이터가 아니므로 삭제하지 않는다.
다른 회원이 삭제 대상 약관을 참조한다면 그 연결만 해제하고, 해당 회원의 분석 결과와 가입 담보는 보존한다.

## 트랜잭션과 파일 삭제

회원 행에 쓰기 잠금을 잡고 연관 데이터를 외래 키 순서에 맞춰 한 DB 트랜잭션에서 삭제한다.
삭제할 파일 경로는 메모리상의 이벤트에 담아 두고 DB 커밋 후에만 파일 삭제를 시도한다.
DB 변경이 롤백되면 파일 삭제도 실행하지 않는다.

파일 삭제용 테이블이나 재시도 스케줄러는 사용하지 않는다.
파일 하나의 삭제가 실패해도 나머지 파일은 계속 처리하며, 실패 경로와 예외를 로그에 남긴다.
`204`는 회원 DB 데이터 삭제가 커밋됐다는 뜻이다. 파일 삭제 실패는 탈퇴를 되돌리지 않으며,
자동 재시도하지 않는다. 실패 파일은 로그의 경로를 확인해 수동으로 정리해야 한다.
커밋 직후 프로세스가 중단되면 아직 삭제하지 못한 경로가 유실될 수 있다.

V15가 이미 적용된 DB의 이력을 보존하기 위해 해당 파일은 유지하고,
V16에서 `pending_document_deletions` 테이블을 제거한다. 아직 V15를 적용하지 않은 DB도
순서대로 V15와 V16을 거친 후에는 이 테이블이 남지 않는다.
기존 테이블에 미완료 작업이 있다면 파일 경로 유실을 막기 위해 V16이 중단된다.
그때는 기존 작업의 파일을 수동 삭제하고 완료한 작업 행을 지운 뒤 다시 기동한다.

S3 사용 시 서버 IAM 계정에 해당 prefix의 `s3:DeleteObject` 권한이 있어야 한다.

## 인증 및 외부 연동

JWT 필터가 매 요청마다 회원 존재 여부를 확인하므로, 기존 액세스 토큰도 탈퇴 후 인증되지 않는다.
리프레시 토큰 저장소에는 회원별 인덱스가 없어 `SCAN`으로 기존 토큰을 찾아 폐기한다.
토큰 재발급 역시 회원 조회에 실패하므로 삭제된 계정의 세션이 되살아나지 않는다.

이 기능은 이 서버가 관리하는 DB와 문서 저장소를 대상으로 한다.
카카오 계정 자체 삭제나 카카오 연결 해제, 별도 AI 서버의 파일·캐시 삭제는 수행하지 않는다.
S3 버전 관리나 별도 백업에 보존된 데이터가 있다면 해당 보존 정책에 따른 추가 처리가 필요하다.

## 검증

```sh
./gradlew test
```

회원 탈퇴 통합 테스트는 H2에서 실제 외래 키와 JPQL 삭제를 검증한다.
Redis와 S3 호출은 모킹하며 운영 데이터는 변경하지 않는다.
