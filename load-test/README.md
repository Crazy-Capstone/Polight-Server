# 부하 테스트 (k6)

챗봇 질문 API에 동시 요청을 걸어 응답 시간과 실패율을 잰다.

## 왜 하는가

챗봇 질문은 `백엔드 → polight-ai → OpenAI` 순으로 흘러간다. OpenAI 는 요청을 동시에 처리하지만, polight-ai 의
`query_policy`(`app/api/routes/rag.py`)가 `async def` 안에서 동기 함수 `answer_question` 을 그대로 부르고 있다. 그러면
OpenAI 응답을 기다리는 동안 이벤트 루프가 멈추고, uvicorn 프로세스가 하나뿐이라 **질문이 한 번에 하나씩만 처리된다**고 본다.

이 가설이 맞다면 동시 사용자가 늘수록 응답 시간이 계단처럼 늘어난다(1건 5초면 5명째는 약 25초). 백엔드의
`rag-read-timeout`(60초)을 넘는 요청부터는 실패한다.

수정 전 수치를 먼저 남기고, AI 서버를 고친 뒤 같은 조건으로 다시 재서 비교한다.

## 대상

배포된 EC2 의 백엔드를 내 PC 에서 호출한다.

```
내 PC (k6) ──HTTP :80──> EC2 polight-backend ──내부망──> polight-ai ──> OpenAI
```

| 항목 | 값 |
|---|---|
| 주소 | `http://<EC2 퍼블릭 IP 또는 도메인>` (`docker-compose.prod.yml` 이 `80:8080` 으로 연다) |
| API | `POST /api/v1/trips/{tripId}/chat/messages` |
| 본문 | `{ "question": "..." }` |
| 인증 | `Authorization: Bearer <access token>` |

polight-ai 는 포트를 열지 않아 밖에서 직접 부를 수 없다. 백엔드를 거쳐 재므로 사용자가 겪는 응답 시간이 그대로 나온다.

로컬이 아니라 EC2 인 이유: 측정에는 "분석 완료 + 약관 연결"된 여행이 필요한데, 증권 분석 요청 경로(`AiClientConfig`,
`FastApiAnalysisClient`)는 `storage.type=s3` 일 때만 켜져 로컬 기본 설정으로는 그 데이터를 만들 수 없다.

## 준비

### 1. k6 설치

테스트 대상 서버가 아니라 **부하를 거는 쪽(내 PC)**에 설치한다. 같은 서버에서 돌리면 k6 가 Spring·Postgres·AI 서버와 자원을
나눠 써서 수치가 흐려진다.

```bash
brew install k6
```

### 2. 접근 확인

EC2 보안 그룹이 내 PC 에서 80 포트로 들어오는 것을 허용하는지 먼저 확인한다.

```bash
curl -i http://<EC2 주소>/api/v1/trips
```

401 이 오면 닿은 것이다(토큰이 없어서 거절된 것). 응답이 없으면 보안 그룹이나 주소를 본다.

### 3. 테스트용 계정과 여행

- 실제 사용자 계정을 쓰지 않는다. 질문이 전부 운영 DB 의 채팅 이력으로 쌓인다.
- 여행에 **분석이 완료된 증권**이 있고 **약관이 연결**되어 있어야 한다. 약관이 없으면 백엔드가 AI 를 부르지 않고 바로 답해
  (`ChatQueryService.NO_TERMS_ANSWER`) 측정이 되지 않는다. 앱에서 증권을 올려 분석을 끝낸 뒤, 보장 확인 화면에 약관 근거가
  보이는지로 확인한다.
- **수정 전과 수정 후에 각각 새 여행을 쓴다(같은 증권으로).** 여행 하나에 채팅 세션이 하나이고, 질문마다 직전 대화
  10개(`ai.server.chat-history-size`)를 AI 에 함께 보낸다. 같은 여행을 이어 쓰면 수정 후 측정은 이력이 꽉 찬, 프롬프트가 더 긴
  상태로 시작해 조건이 달라진다.

### 4. 액세스 토큰

EC2 의 `/auth/login/kakao` 테스트 페이지로 로그인해 액세스 토큰을 얻는다. 기본 만료가 1시간
(`SECURITY_JWT_ACCESS_TOKEN_EXPIRY_SECONDS`)이라 측정 직전에 받는다. 측정이 길어져 401 이 섞이면 실패율이 왜곡되니, 그때는
설정을 바꾸지 말고 토큰을 다시 받는다.

**토큰을 파일에 적거나 커밋하지 않는다.** 실행할 때 환경 변수(`-e TOKEN=...`)로만 넘긴다.

## 측정 방법

### 조건 고정

수정 전후 비교가 성립하려면 아래를 바꾸지 않는다.

- 같은 질문 문장 (답변 길이가 달라지면 응답 시간도 달라진다)
- 같은 여행·약관
- 같은 답변 모델 (polight-ai `answer_provider`)
- 같은 측정 위치 (같은 PC, 같은 네트워크)
- 백엔드 설정: `ai.server.rag-read-timeout`(60초)이 실패 기준선이다. 수정 전후에 바꾸지 않는다

### 순서

1. `vus=1` 로 질문 1건의 기준 응답 시간을 잰다.
2. `vus` 를 1 → 5 → 10 으로 올리며 각각 잰다.
3. 직렬 처리라면 응답 시간이 사용자 수에 비례해 늘어난다.

### 주의

- **운영 서버다.** 측정하는 동안 실제 사용자도 같이 느려진다. 사용자가 없는 시간대에 하고, 팀에 미리 알린다.
- **OpenAI 비용이 실제로 나간다.** 작게 시작한다(`vus` 5 이하, 20초 내외).
- 지금 구조에서는 측정 중에 polight-ai 의 분석 요청 접수와 약관 매칭도 함께 멈춘다. 그 시간에 누가 증권을 올리면 분석 요청이
  타임아웃으로 실패할 수 있다.
- 같은 EC2 에 Postgres·Redis·백엔드·AI 가 메모리 제한을 걸고 함께 떠 있다. 측정 중에 EC2 에 SSH 로 접속해
  `docker stats` 로 메모리를 지켜본다.
